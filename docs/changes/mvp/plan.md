# Plan: building the Accountable MVP

This plan says how to build what `docs/changes/mvp/intent.md` asks for and `docs/spec.md` specifies. The look follows `docs/mockups/final-dashboard.html` and `docs/mockups/final-pipeline.html`. The MVP has been built to this plan; progress is in `docs/STATUS.md`.

## How to read the IDs

Every row has an ID, and every ID links to where it's defined.

| Prefix | Meaning | Defined in |
| --- | --- | --- |
| G, T, O, C, D, P, A, H, V, S | Spec requirements, such as D3 | [spec.md, Requirements](../../spec.md#requirements) |
| DS1, DS2 | Spec design: screens and brand | [Screens](../../spec.md#screens), [Brand](../../spec.md#brand) |
| CN1 to CN11 | Spec concerns, numbered as in the spec, all confirmed | [spec.md, Concerns](../../spec.md#concerns) |
| SC1 to SC8 | Intent success criteria, in order | [intent.md, Success criteria](intent.md#success-criteria) |
| ES1 to ES4 | Intent's "in everyday use" success, in order | [intent.md, Success criteria](intent.md#success-criteria) |
| PH | Phases | [Order of work](#order-of-work) |
| W | Work items, numbered by phase | [Order of work](#order-of-work) |
| R | Risks | [Risks](#risks) |
| TB, TF, TE, TM | Backend, frontend, end-to-end and by-hand tests | [Proof](#proof) |

[Traceability](#traceability) at the end ties each requirement to the work, tests and risks.
